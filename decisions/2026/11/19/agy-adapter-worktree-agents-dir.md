# Antigravity CLI adapter keeps its hooks, skill and protocol in the worktree

## Context

`agy` (Antigravity CLI, 1.5.12 checked) has no system-prompt flag, and its `--settings` carries only settings.json keys, never hooks, skills or prompts. It reads customization from `~/.gemini/config/` and from `.agents/` found by walking up from its cwd. Users often start it through a launcher that overrides HOME. A rule file is capped at 24 KB and the dev3 protocol is about 32 KB. It has no hook for a permission wait and none for a session end, but its statusLine payload carries `quota`, `email`, `plan_tier`, `conversation_id` and `tool_confirmation_pending`. Its quit command is `/quit` (also `/exit`). `agy models` prints one `<slug>  <display name>` per line, effort baked into the slug.

## Decision

Everything dev3 needs goes into `<worktree>/.agents/` (`writeAgyHooks` in `src/shared/agent-hooks.ts`, `setupAgyWorktreeConfig` in `src/bun/agent-hooks.ts`): `hooks.json` gets one entry keyed `dev3` (other keys are kept, an unparsable file is left alone) and `skills/dev3/SKILL.md`. Both are excluded via `.git/info/exclude`; a dev3-unowned folder, a symlinked path, or a file git tracks (`isGitTracked`, each file judged on its own) gets nothing and a logged warning: a tracked `hooks.json` is the team's, so merging into it would leave a change to commit, and such a task gets no agy status hooks. An untracked existing `hooks.json` is still merged. `dev3 hook agy` answers `SessionStart` with the protocol as `injectSteps` `systemMessage` (`skillBodyFor("agy", "worktree")`, rendered CLI-side), moves the task on `PreInvocation` and `Stop`, and records `conversationId` on the pane so resume runs `--conversation <id>` (`--continue` without one). A `Stop` with `terminationReason` `ERROR` reuses the Claude stop-failure path. The adapter sets no `skillFamily`, so a task in a shared folder still gets the shared-folder notice in its launch prompt.

Each launch also passes a per-session `--settings` (`agySessionSettings`, `src/shared/agent-adapters/agy.ts`), which agy never saves:

- `trustedWorkspaces`. agy matches a trusted workspace only by its REALPATH (verified on 1.5.12: `/private/tmp` works, `/tmp` does not), so the backend resolves it (`realWorktreePath` in `src/bun/agents.ts`) and hands it to the pure adapter through `AdapterLaunchOptions.agy`.
- `permissions.allow`: one `command(<cli> <words>)` rule per `DEV3_AUTO_APPROVED_SUBCOMMANDS` entry and per spelling of the CLI (bare `dev3`, `~/.dev3.0/bin/dev3`, the expanded `<account home>/.dev3.0/bin/dev3` the hook commands show the agent), the same list Claude's allowlist uses, so nothing that starts a process is pre-approved.
- A `statusLine` (`dev3 statusline agy`, `stack_with_default`). It prints nothing and swallows every error. It dumps the quota per account to `~/.dev3.0/data/rate-limits/agy/<sha256(email)[:16]>.json`, so no email is ever a file name; `src/bun/rate-limit-monitor.ts` reads those dumps like Claude's and the usage panel shows one read-only "Antigravity" row per account. A `remaining_fraction` bucket is a window; `disabled` and amount-only buckets are skipped, since a window carries a percentage. Real buckets (Google AI Ultra) are `gemini-5h`, `gemini-weekly`, `3p-5h`, `3p-weekly` (`3p` = third-party models inside agy), shown in that order as 5-hour, weekly, other models 5-hour, other models weekly; the header pill keeps only the first two. `quota` and `plan_tier` are absent until a conversation starts, so a payload without a usable bucket never overwrites the last dump. With rate-limit tracking off the command runs with `--no-limits`: no dump, but permission waits still flow.
- The same statusLine turns `tool_confirmation_pending` into a `PermissionRequest` (→ `user-questions`) and, when it clears, a `PostToolUse` (back to the remembered lane). agy refreshes the line constantly, so the last state per task is kept in `~/.dev3.0/data/agy-statusline/<taskId>.json` and only a change is sent; an unconditional `PostToolUse` would pull a task that asked a question itself back to `in-progress`. A `conversation_id` the board has not seen is recorded through `task.agentHook` with `captureOnly`, which moves nothing.

The hook and statusLine commands spell the dev3 CLI as the absolute `<account home>/.dev3.0/bin/dev3` (`agyHookDialect`; the backend passes `resolveAccountHome()`, i.e. `os.userInfo().homedir`, in, and `src/shared` stays pure), because agy and `sh` expand `~` against a launcher's overridden HOME (found in a live check). The base is the account home, not `$HOME` and not a redirected `DEV3_HOME`: the machine-wide CLI exists only at `<account home>/.dev3.0/bin/dev3`. `POSIX_DEV3_CLI` is frozen and left alone for every other agent; the agent's own calls stay bare `dev3`, as the launcher keeps PATH. A path with a space is quoted and its quotes escaped inside `sh -c '...'`.

`notifications` is deliberately not set: with it agy rings the terminal bell at every turn end, and dev3's bell auto-transition moved the card to `user-questions` against the Stop hook (live check). `hooksReportPermissionWaits` is true, which makes dev3 ignore agy's bell altogether; the only permission-wait signal is the statusLine's `tool_confirmation_pending` (live: true together with `agent_state: "tool_use"` while the prompt shows). The cost: a wait is missed when the statusLine does not run. agy's default `agentMode` is Auto, so most dev3 metadata commands run unprompted anyway.

The model probe is `agy models`; slugs fold to the model family by stripping the trailing `-low|medium|high|xhigh|max`, like Cursor's.

## Risks

A resumed conversation receives the protocol again at `SessionStart`, since agy gives no way to tell resume from start. The Settings lean-protocol toggle does not reach agy: the hook always renders the full body. Tasks in a folder dev3 does not own run without hooks (status does not move on its own), though the `--settings` statusLine still reports waits and quota there. `buildResumeCommand` has no worktree path, so a recovery command carries no `--settings`. The pending-confirmation state is written optimistically: a report that failed to send is not retried until the flag flips again. The allow rules cover the bare `dev3` spelling only. Verified live on agy 1.5.12: the realpath trust, the allow rules, `hooks.json` from the worktree, `SessionStart` injection, `PreInvocation`, `Stop`, the conversation id and `tool_confirmation_pending`.

## Alternatives considered

Global `~/.gemini/config` hooks: rejected because a launcher that overrides HOME never reads them. A rules file for the protocol: rejected because of the 24 KB cap. Writing `trustedWorkspaces` into `~/.gemini/antigravity-cli/settings.json`: rejected for the same HOME reason and because it would edit a user file. Pre-assigning the conversation id: agy has no flag for it, so the id is captured from the hook. Sending `PostToolUse` on every refresh with no pending flag: rejected, see above.
