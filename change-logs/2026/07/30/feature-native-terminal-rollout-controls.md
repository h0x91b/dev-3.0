Short: Pick the terminal backend for new tasks

Global Settings → Terminal now has a machine-local "Terminal backend for new tasks" picker, stored in its own versioned file (`~/.dev3.0/terminal-backend.json`) so an older side-by-side install cannot silently drop it: keep tmux (today's default) or opt new tasks into the experimental native terminal. The native option stays visible but disabled, with the exact reason and fix, when the build cannot resolve a native terminal host, and tmux is shown as unavailable on Windows, which has no tmux runtime. Task details gained a matching per-task override for the next launch, locked with an explanation while a live terminal owns the task. Existing tasks are never rewritten and a native launch failure never falls back to tmux; `dev3 task terminal-backend` remains the expert equivalent and now shares the same guard.
