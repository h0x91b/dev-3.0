Short: dev3 now boots on Windows

The dev3 desktop app now builds and starts on Windows without Git Bash, WSL or a system Bun: the build path no longer invokes any shell script, the packaged app ships its own `dev3.exe`, and `bun run dev` / `bun run start` run as a plain process chain instead of a POSIX shell line. Boot itself was made Windows-safe — the data root resolves from `%USERPROFILE%` rather than guessing `/tmp`, the shell default falls back to PowerShell, and the Unix-socket CLI transport reports itself unavailable instead of crashing before the first window. Generated wrapper scripts and Claude/Codex hook commands now have a Windows spelling (PowerShell scripts, absolute `dev3.exe` paths, no tilde or shell operators), and the packaged Windows archive is verified in CI by launching the real app and proving a clean shutdown. Projects and worktrees also get a Windows-safe storage key (a drive-qualified path is not a legal directory name), the folder picker can reach other drives, worktree cloning no longer shells out to `cp`/`rm`/`mkdir`, and the remote web UI serves its assets there at all. A task started there really creates its worktree, copies the shared paths without freezing the UI, finds the packaged native terminal host the build ships, and writes its launch script to the OS temp directory. Windows CLI-to-app IPC is still missing, so `dev3` commands and agent hooks do not reach the app there yet, and a task's terminal backend can still only be switched from the CLI.
