Rebase now runs against the base the branch dropdown promises. In a project with no git remote the button announced the local base branch and then ran `git rebase origin/<base>`, which died with `fatal: invalid upstream` after a failed fetch it had already swallowed — the `params.compareRef || origin/<base>` fallback fired on the normal path, because the renderer sends an empty compare ref whenever the server owns the choice. Every git action now resolves its ref through the one resolver, no fetch is attempted without a remote, a rebase target that does not exist is refused before a pane opens, and a failed rebase distinguishes "stopped on conflicts" from "refused before touching your branch" instead of always telling you to resolve conflicts. Line counts on the Stats screen change for local-only projects: they were measured against a ref that does not exist there and are now measured against the local base.
