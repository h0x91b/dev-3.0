Short: Diagnose native dev-server stop freeze

Diagnosis pass on the UI freeze after Stop Dev Server on a native task; the freeze itself is still unconfirmed, so nothing changes behaviour. Client-local pane focus now follows the pane set, so closing the focused dev-server pane hands focus to a surviving pane instead of leaving nothing focused and the viewer bar bound to a pane that is gone. Dev Server start, stop and poll now carry a renderer-minted correlation id that the matching handler echoes, so a click that never reached its handler is distinguishable from one that ran and hung; native viewer WebSocket lines carry the pane id, a stop carries one id from request through aux-pane close to reply, the desktop bridge watchdog reports when it revives the socket, and a terminal teardown over 50 ms says so. Adds a real-native-pane start/stop matrix for one and two viewers on the same pane sessions, plus remote-transport cycle coverage.
