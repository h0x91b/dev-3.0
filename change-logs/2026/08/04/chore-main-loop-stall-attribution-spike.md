Measured which mechanism can name the code that blocks dev3's main event loop, since the existing detector only reports that a tick was late. Bun's in-process JSC sampling profiler does name it, including blocking syscalls and at negligible CPU cost, but collecting it after a 20-second stall spiked memory from 46 MB to 258 MB, and a Worker cannot take that cost off the main thread because the profiler's buffer turned out to be per-VM. The work is therefore parked with nothing user-facing changed: this adds a harness that pins the mechanism and its five hard limits, plus a decision record explaining why it cannot ship yet and which option is left.
