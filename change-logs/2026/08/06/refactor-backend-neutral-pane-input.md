Added one internal backend-neutral way to inject terminal input into a named task pane, ready for terminal workflows to build on. A tmux stage goes out as a single guarded command that checks the pane's session, its server's own generation token, that the pane is alive and that it is not sitting in copy mode before sending, so a moved pane, a restarted server or a scrolled-back pane cannot receive stray input. Delivery is at-most-once within one executor process and pane incarnation, with an honest verdict instead of a boolean, and the native backend reports uncertainty until its host can acknowledge input.
