The required status checks on main now wait for the packaged Windows jobs instead of merging ahead of them: the Windows packaging workflow became a reusable workflow called from build.yml, and its 45-entry path filter moved into code as a single source of truth so out-of-scope pull requests still skip it. A pull request can no longer merge while the Windows proof is still pending, and a Windows job that did not run says so out loud rather than passing in silence. Three existing tests ride along because they read what this change reshapes: the Bun-pin proof invariant now reads the scope list as a typed import instead of parsing the deleted filter, the registry isolation guard matches import specifiers instead of any file that merely names the directory in a string, and the terminal e2e gate checks that it is in the required job's dependency list rather than that the list is exactly two entries long.
