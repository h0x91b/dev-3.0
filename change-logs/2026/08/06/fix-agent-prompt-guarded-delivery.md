Short: Honest answers when a prompt is sent

Handing a task off to its agent — Create PR, Commit, the rebase-conflict prompt, `dev3 message` and scheduled messages — now reports three answers instead of two: delivered, not delivered, or sent-but-unconfirmed. The last one used to be silently reported as success, which mattered most for scheduled messages: they leave the queue whichever way it goes, so a message that never arrived looked delivered and was unrecoverable. `dev3 message` exits with the new code 11 for it, so an agent no longer re-sends a message that may already have landed. On tmux the prompt is also now pinned to the exact pane and server it was sighted in, and a message whose text reads like a key name (`C-c`, `Escape`) is finally typed into the agent rather than pressed as that key.
