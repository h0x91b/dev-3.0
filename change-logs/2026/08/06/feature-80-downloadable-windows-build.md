Short: Download the packaged Windows build

CI already built the real Windows app, launched it and proved it reached a window — then discarded it, so nobody could obtain the thing we prove works. The packaged Windows job now publishes the extracted app tree it actually launched as a `windows-app-<sha>` artifact kept for 30 days, and writes a run summary naming the artifact, the exact executable to double-click, and what an unsigned build looks like on Windows (SmartScreen, unknown publisher). The uploaded bytes are the launched bytes, not a re-extraction: the run summary is generated from the launch proof, so it cannot advertise a file nothing started, and a failed proof publishes nothing. The upload lives in the reusable packaging workflow, so releases emit the same artifact — that behaviour reaches `release.yml` without editing it. The build is still `--env=canary`; that is safe only while the channel is a name (artifact and app naming plus a `build.json` field, no published Windows update feed) and must be re-examined when real channel semantics land. The self-extracting Windows installer is built by the same job and has never been launched by anything, so it is deliberately not handed out — a known gap recorded in `decisions/2026/08/06/downloadable-windows-build-is-the-launched-tree.md`, not an oversight.
