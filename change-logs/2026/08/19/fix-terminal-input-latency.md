Short: Typing echoes about 33 ms sooner

Terminal text is drawn from a glyph cache now instead of being re-shaped character by character on every frame, which is what WebKit was charging most of the frame for. Output whose colours never repeat cannot be cached at all, so the cache notices within a couple of frames, switches itself off and hands its memory back rather than paying for a cache nobody hits. Separately, the terminal no longer holds PTY output for an animation frame before handing it to the emulator, and the app no longer waits out the full 16 ms batch window before sending a lone keystroke echo — together roughly 33 ms off every character you type. A fast scroll flick now delivers the lines the pacer held back instead of dropping them, so scrolling stops short less often. Terminal performance is also measured now, and View → Debug → Terminal Performance shows it live per pane: frame rate, the gap between painted frames, frames that missed their slot, PTY throughput, wheel-to-tmux scroll rate, and keystroke-to-pixel latency (also readable from devtools as `window.__dev3TerminalLatency()`, with a summary in the log every minute).
