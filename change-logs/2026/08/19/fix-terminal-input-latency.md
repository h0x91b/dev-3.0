Short: Terminal keeps up with a flood

The terminal no longer holds PTY output for an animation frame before handing it to the emulator, and the app no longer waits out the full 16 ms batch window before sending a lone keystroke echo — together roughly 33 ms off every character you type. A fast scroll flick now delivers the lines the pacer held back instead of dropping them, so scrolling stops short less often. A command that floods the screen faster than it can be drawn no longer replays minutes of history in slow motion: output the terminal cannot keep up with is skipped and the pane is redrawn from tmux, so the screen stays on the present instead of falling further behind. Terminal performance is also measured now, and View → Debug → Terminal Performance shows it live per pane: frame rate, the gap between painted frames, frames that missed their slot, PTY throughput, how far behind the viewer is, wheel-to-tmux scroll rate, and keystroke-to-pixel latency (also readable from devtools as `window.__dev3TerminalLatency()`, with a summary in the log every minute).
