Short: Safe reset when moving back to To Do

Moving a running task back to To Do now asks first. If you confirm, it resets the task: the agent stops, the worktree is removed, and only branches dev3 created for the task are deleted, each noted with a recovery command first. The card stays in To Do and starts fresh next time. Before this change, the move could silently wipe the task's branch and commits on the next start, and agent hooks or `force` retries can no longer restart or reset a To Do card. Starting a task again no longer deletes a leftover branch or folder from an earlier run that still holds commits or uncommitted files; it stops and says what to keep. The same fix stops agents, dev servers and panes from launching in your home folder when a task's worktree is missing, and shows a "can't read this folder" notice without destructive buttons when disk access is lost.
