Short: Codex launches survive its sandbox

Codex on macOS could not start a session when its permission profile lacked full-disk read, dying with `fs sandbox helper failed ... sandbox-exec: execvp() of '/opt/homebrew/bin/codex' failed: Operation not permitted` — its sandbox helper re-execs the binary through a path its own policy does not allow, which every Homebrew install hits because the binary there is a symlink. dev3 now starts Codex by its resolved path, with every permission grant unchanged. The fallback `workspace` profile dev3 writes into `~/.codex/config.toml` also grants `":root" = "read"` instead of `":minimal" = "read"`, matching Codex's own default rather than narrowing Codex runs outside dev3; an existing profile is never rewritten, because dev3 cannot tell its own older output from a hand-written one.
